# SkillToolset reference

Verified against `google/adk-python@v2.12.0`
(`src/google/adk/tools/skill_toolset.py`, `src/google/adk/skills/`).

## Constructor

```python
SkillToolset(
    skills: list[Skill] | None = None,
    *,
    registry: SkillRegistry | None = None,
    code_executor: BaseCodeExecutor | None = None,
    environment: BaseEnvironment | None = None,
    skills_folder: str | Path | None = None,
    script_timeout: int = 300,
    save_output_artifacts: bool = False,
    additional_tools: Sequence[ToolUnion | BaseNode] | None = None,
    tool_name_prefix: str | None = None,
    tool_filter: ToolPredicate | list[str] | None = None,
    discovery_mode: SkillDiscoveryMode = SkillDiscoveryMode.LAZY,
    lifecycle_config: SkillLifecycleConfig | None = None,
)
```

Raises `ValueError` when:

- both `code_executor` and `environment` are given;
- `skills_folder` is given without `environment`;
- `skills_folder` is relative (it must be absolute);
- two skills share a name.

`save_output_artifacts` is only supported with `code_executor`, not
`environment`.

## Discovery

| Mode | Behaviour | Cost |
|---|---|---|
| `LAZY` (default) | `list_skills` tool; catalog stays out of the system instruction | One model turn before the first load |
| `EAGER` | Catalog injected as XML; no `list_skills` | Names in every prompt |

Registry skills are reachable only through `search_skills` in both modes.

## Lifecycle

```python
from google.adk.tools.skill_toolset import (
    SkillLifecycleConfig, SkillLifecycleMode,
)

config = SkillLifecycleConfig(
    enabled=True,
    default_mode=SkillLifecycleMode.BOUNDED,
    max_active_skills=5,
    skill_overrides={"long-reference-skill": SkillLifecycleMode.EPHEMERAL},
    revalidate_skills=False,
)
```

- `enabled=False` leaves every skill active for the session regardless of the
  other fields.
- `PERSISTENT` never counts against `max_active_skills` and is never evicted.
- `BOUNDED` counts; past the cap the least-recently-loaded bounded skill is
  released. Reloading counts as a use.
- `EPHEMERAL` expires at the end of the turn that loaded it. Under `run_live`
  there is no turn boundary, so it behaves as `PERSISTENT`.
- `revalidate_skills=True` re-reads registry skills each turn and re-states
  changed ones. It costs a lookup per active skill per turn and invalidates
  the prompt cache; default off.

`ADK_ENABLE_SKILL_LIFECYCLE=1` is a separate experimental feature flag. It
gates only the `unload_skill` tool and the pruning of unloaded instructions —
not `BOUNDED` or `EPHEMERAL`.

## Registry interface

```python
from google.adk.skills import SkillRegistry

class MyRegistry(SkillRegistry):
    async def get_skill(self, *, name: str) -> Skill: ...
    async def search_skills(self, *, query: str) -> list[Frontmatter]: ...

    # Optional: override to teach the model how search works here.
    def search_tool_description(self) -> str | None: ...
```

`get_skill` must raise when the skill does not exist; `search_skills` returns
L1 metadata only, never bodies.

## Tool behaviour

### `load_skill_resource`

Arguments: `skill_name`, `file_path`, where `file_path` must start with
`references/`, `assets/`, or `scripts/`.

Success: `{"skill_name", "file_path", "content"}`. Binary content is returned
as a notice instead of bytes.

Failure codes:

| Code | Meaning |
|---|---|
| `INVALID_ARGUMENTS` | Missing `skill_name` or `file_path` |
| `INVALID_RESOURCE_PATH` | Path does not start with an allowed prefix |
| `REGISTRY_ERROR` | Registry fetch raised |
| `SKILL_NOT_FOUND` | No such skill |
| `RESOURCE_NOT_FOUND` | First miss in this invocation |
| `RESOURCE_NOT_FOUND_FATAL` | Second miss in the same invocation |

The miss counter is invocation-scoped and counts **all** paths, so retrying a
different guessed path still escalates. After the fatal response the model is
told to stop and report.

### `run_skill_script`

With an `environment`, arguments are `skill_name`, `file_path`, and a
`command` string. With a `code_executor`, arguments are `skill_name`,
`file_path`, and either `args` (object or list) plus optional
`short_options` / `positional_args`.

- `script_timeout` defaults to 300 seconds and applies to subprocess
  execution; Python scripts run via `exec()` are not covered by it.
- `run_skill_script` is dropped from the offered tools when no executor or
  environment is configured.
- Files generated by a script can be saved as artifacts only when
  `save_output_artifacts=True` and a `code_executor` is present.

## State injection

`metadata.adk_inject_state: true` enables `{var}` interpolation in the L2 body
when the skill is loaded through `load_skill`, using the same syntax as
`LlmAgent.instruction`:

- `{var}` — value from session state; missing key raises.
- `{var?}` — empty string when missing.
- `{artifact.name}` — artifact contents.

## Loading APIs

| Function | Returns |
|---|---|
| `load_skill_from_dir(dir)` | One `Skill` |
| `load_skills_from_dir(dir)` | `list[Skill]`, skipping folders without `SKILL.md` |
| `list_skills_in_dir(dir)` | `list[Frontmatter]`, no L2/L3 |
| `*_async`, `*_gcs_dir` variants | Same contracts, async / GCS |
